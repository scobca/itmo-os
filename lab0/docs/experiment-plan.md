# План эксперимента `graph_traverse`

Цель — проверить [гипотезу](hypothesis.md), сравнив время обхода последовательного и случайного графов при записи без
системного кэша.

План исходит из конфигурации `--write --no-cache`, использованной в основной гипотезе. Правила интерливинга, выбора `N`
и обработки результатов остаются теми же.

## Конфигурации

| Обозначение | Команда                                                                 |
|-------------|-------------------------------------------------------------------------|
| `seq`       | `taskset -c 2 ./out/graph_traverse --write --no-cache 1 graph-seq.bin`  |
| `rand`      | `taskset -c 2 ./out/graph_traverse --write --no-cache 1 graph-rand.bin` |

Оба графа создаются с одинаковым размером 1 MiB и seed `427`. Размер уменьшен относительно предварительных 5 MiB,
поскольку один запуск занимал 39–43 секунды, то есть больше рекомендуемых 20–30 секунд.

```sh
python3 ../util/graphgen.py -s 1M --seed 427 --topology chain \
  -b 0.5 --min-step-pages 2 -o graph-rand.bin

python3 ../util/graphgen.py -s 1M --seed 427 \
  --topology sequential -o graph-seq.bin
```

## Методика

1. Основная метрика одного запуска — полное время `real` в секундах. Дополнительно сохраняются `user`, `sys`,
   переключения контекста и page faults из `/usr/bin/time`.
2. Перед измерениями выполняется по одному прогревочному запуску каждой конфигурации. Эти два результата заранее
   исключаются из статистики.
3. Состояние файлового кэша одинаково для всей серии: каждый запуск выполняется с `--no-cache`. Ручной `drop_caches` не
   используется.
4. Процесс всегда закрепляется за логическим CPU 2 через `taskset`. Фоновая нагрузка, `strace`, `perf` и `stress-ng` во
   время финальной серии не запускаются.
5. Запуски интерливируются блоками: в нечётном блоке `seq → rand`, в чётном — `rand → seq`. Между запусками
   выдерживается пауза 2 секунды, будем надеяться что порядок уменьшит влияние нагрева, фоновых процессов и временного
   дрейфа системы =)
6. Каждый запуск и его метаданные сохраняются отдельной строкой CSV. Предварительные результаты
   из [характеризации](characterization.md) в финальную выборку не включаются.

## Число повторов

Сначала выполняется пилотная серия по `N = 10` измерений каждой конфигурации. По ней вычисляются среднее `mean` и
выборочное стандартное отклонение `s`.

Целевая точность — 95%-й доверительный интервал с относительной полушириной не более 5% среднего. Ориентировочное число
повторов вычисляется отдельно для `seq` и `rand`:

```text
E = 0,05 × mean
N ≈ (1,96 × s / E)²
```

Для полной серии берётся большее из двух полученных значений `N`, округлённое вверх. После сбора строится точный 95%-й
доверительный интервал по t-распределению Стьюдента. Если интервал остаётся шире 5% - будем увеличивать число повторов

## Прогрев (даст бог не сгорим)

- Один прогревочный запуск каждой конфигурации (мы его выкидываем)
- Результат запуска исключается только при ненулевом коде завершения, причину впишем отдельно 

## Порядок выполнения

1. Генерируем новые графы
2. Фиксируем состояние системы согласно шагу 4.6
3. Выполняем прогрев 
4. Провести интерливированную пилотную серию с `N = 10`.
5. Считаем требуемое `N` и при необходимости добираем измерения, сохраняя тот же порядок и окружение.
6. Сохраняем сырые данные в `lab0/logs/final/graph-traverse-write-nocache.csv` и повторно снимаем состояние системы после
   серии.
7. Считаем среднее, стандартное отклонение, медиану, IQR и 95%-й доверительный интервал для обеих конфигураций.
